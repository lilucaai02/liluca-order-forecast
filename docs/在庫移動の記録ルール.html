在庫移動の記録ルール

記入するのは「発注と在庫移動一覧」シートだけです。
商品タブ（TG-01(在庫)、マウスピース(在庫)など）には書かないでください。

まず覚えていただきたいこと

書く場所「発注と在庫移動一覧」シートの一番下の行
反映まで10分以内に自動で商品タブへ反映されます
入力する項目移動日・商品SKU・移動元・移動先・個数・状態（＋到着時は今到着個数・最後到着日付）
触ってはいけない項目データ更新・データ日付・到着個数/発送個数・納品内容・運送時間 — 自動計算されます
入力位置への移動A列をクリックして ⌘ + ↓ → ↓ で最終行の次に飛べます

1. どこがAPI連携されているか

場所在庫数の取得到着の検知
FBA（Amazon）毎朝 自動完全自動
RSL（楽天）毎朝 自動スタッフが記入
Stock Crew（Yahoo）毎朝 自動スタッフが記入
イーウーパスポート　中国なし（記録から計算）スタッフが記入
荒瀬倉庫（amazon用／以外）なし（記録から計算）スタッフが記入
事務所（amazon用／以外）なし（記録から計算）スタッフが記入
発注中・輸送中なし（記録から計算）—

到着が完全自動なのはFBAだけです。Amazonが「いま何個が入荷作業中か」をデータで教えてくれるためです。分納（500個が100個ずつ届く）もそのまま追えます。

イーウーパスポート・荒瀬倉庫・事務所には在庫を確認する仕組みがありません。記録から計算しているだけなので、書き漏らすと在庫が合わなくなります。

【4】発送したものが到着したとき

ここだけ、到着先によって作業が変わります。

4-1. FBA（Amazon）に届いた

何もしなくてOKです

Amazonから自動で入荷情報を取得して処理します。分納で何回に分かれて届いても自動です。

4-2. FBA以外に届いた

対象：RSL・Stock Crew・荒瀬倉庫・事務所・イーウーパスポート中国

スタッフが「発注と在庫移動一覧」の、発送したときの行（【3】で書いた行）に追記します。新しい行は作りません。

項目入れるもの
今到着個数届いた累計の数
最後到着日付最後に届いた日

→ 自動で「輸送中」が減り、到着先の在庫が増えます

分納のときは、同じ行の「今到着個数」を書き換えてください。
例：500個送って200個届いた → 200 と記入
　　さらに300個届いた → 500 に書き換え（合計を書きます）
全部届くと、状態が自動で「到着」に変わります。

【5】数が合わないとき（ずれ修正）

検品で不良品が出た、棚卸で数が違った、発注より多く届いた——こういう「移動ではないけれど数が変わる」ときの書き方です。

スタッフが「発注と在庫移動一覧」に新しい行を1行記入

5-1. 数を減らすとき（不良品・棚卸で少なかった）

項目入れるもの
移動日気づいた日
商品SKU商品を選ぶ
移動元減らす場所を選ぶ
移動先空欄のまま
個数減らす数（マイナスは付けません）
状態到着
備考欄理由を書く（例：不良品）

→ その場所の在庫だけが減ります。どこにも移動しません

5-2. 数を増やすとき（多く届いた・棚卸で多かった）

項目入れるもの
移動元空欄のまま
移動先増やす場所を選ぶ
個数増やす数
状態到着
備考欄理由を書く（例：ずれ修正）

→ その場所の在庫だけが増えます

覚え方：片方だけ書いて、状態は「到着」。
移動元だけ書く → 減る／移動先だけ書く → 増える
備考欄に書いた理由は、そのまま商品タブのセルのメモに残ります。
到着個数・最後到着日付は書きません（1行で終わりです）。
両方とも空欄にすると発注の扱いになります。ずれ修正のときは、必ずどちらか片方を選んでください。

参考：選べる項目

移動元・移動先（12種類）

イーウーパスポート　中国／中国工場／事務所 amazon用／事務所 amazon以外／荒瀬倉庫 amazon用／荒瀬倉庫 amazon以外／FBA／RSL／Stock Crew／武智商店／就労支援所／アールステージ

状態（3種類）

発注中／輸送中／到着

就労支援所・アールステージは、商品タブに対応する在庫欄がないため、在庫計算に反映されません。

注意：やってはいけないこと

  • 商品タブ（TG-01(在庫)など）に直接書く → 二重計上になります
  • データ更新・データ日付の欄を触る → 自動計算が壊れます
  • 951行目より前の行を編集する → 過去の記録です
  • 記入済みの行の「移動日・個数」を後から変える → ズレの原因になります（訂正は【5】ずれ修正の新しい行で）
  • ずれ修正の行に「今到着個数・最後到着日付」を書く → 1行で完結するので不要です
